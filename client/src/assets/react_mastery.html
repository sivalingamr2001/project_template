Pattern to memorise
import { useState } from 'react'

function Counter() {
  // [currentValue, setter] = useState(initialValue)
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>Count: {count}</p>
      {/* Direct update */}
      <button onClick={() => setCount(count + 1)}>+1</button>
      {/* Functional update — always safe with async state */}
      <button onClick={() => setCount(prev => prev - 1)}>-1</button>
    </div>
  )
}
Golden rule
Never mutate state directly. count = 5 won't re-render. Always use setCount(5).
Functional updates
When new state depends on old state, use setCount(prev => prev + 1). Avoids stale closure bugs.
Object state
Spread to preserve fields: setUser({...user, name: 'Ali'}). React compares by reference.

Pattern — dependency array controls when it runs
useEffect(() => {
  // Runs after render (like componentDidMount/Update)
  const id = setInterval(() => {
    setSeconds(s => s + 1)
  }, 1000)

  // Return cleanup — runs before next effect or unmount
  return () => clearInterval(id)

}, [isRunning])  // ← dependency array

// []        → runs once on mount  (componentDidMount)
// [dep]     → runs when dep changes
// no array  → runs after EVERY render (usually wrong!)
Always clean up
Return a cleanup function for any subscription, timer, or event listener — or you'll get memory leaks.
Fetch on mount
useEffect(() => { fetch('/api/data')… }, []) — the empty array means "only on mount".

Pattern — reducer handles all state transitions
const reducer = (state, action) => {
  switch (action.type) {
    case 'ADD':
      return [...state, { id: Date.now(), text: action.text, done: false }]
    case 'TOGGLE':
      return state.map(t => t.id === action.id ? {...t, done: !t.done} : t)
    case 'DELETE':
      return state.filter(t => t.id !== action.id)
    default: return state
  }
}

const [todos, dispatch] = useReducer(reducer, [])

// Usage — describe WHAT happened, not HOW to update
dispatch({ type: 'ADD', text: 'Learn React' })
dispatch({ type: 'TOGGLE', id: 1234 })

// With — same reference unless `id` changes

  () => doSomething(id),

Chapter 2
Component Architecture
How you structure, split, and compose components determines how painless your codebase is to maintain as it grows.
Presentational
Only cares about how things look. Receives everything via props. No API calls, no business logic. Easy to test and reuse.
Container
Cares about how things work. Manages state, calls APIs, handles logic. Passes data down to presentational components.
Custom Hooks
The modern pattern — extract stateful logic into reusable use* functions. Replaces the need for container components.
Recommended folder structure (feature-based)
src/
├── features/
│   └── auth/
│       ├── AuthForm.jsx      ← presentational only
│       ├── useAuth.js        ← custom hook (all logic lives here)
│       ├── authTypes.js      ← action type constants
│       └── index.js          ← public API of the feature
├── shared/
│   ├── components/         ← Button, Modal, Input…
│   └── hooks/              ← useFetch, useDebounce…
└── App.jsx
Composition over prop explosion
// ❌ Prop explosion — hard to extend or maintain
<Card title="Hello" icon="user" footer="…" headerBg="blue" />

// ✅ Composition — flexible, readable, extensible
<Card>
  <Card.Header><UserIcon /> Hello</Card.Header>
  <Card.Body>Your content</Card.Body>
  <Card.Footer>Actions here</Card.Footer>
</Card>

// Implementation — compound component pattern
function Card({ children }) {
  return <div className="card">{children}</div>
}
Card.Header = ({ children }) => <div className="card-header">{children}</div>
Card.Body   = ({ children }) => <div className="card-body">{children}</div>
Custom hook — the cleanest pattern
// hooks/useFetch.js — write once, use in any component
function useFetch(url) {
  const [data, setData]       = useState(null)
  const [loading, setLoading] = useState(true)
  const [error, setError]     = useState(null)

  useEffect(() => {
    const controller = new AbortController()
    fetch(url, { signal: controller.signal })
      .then(r => r.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false))
    return () => controller.abort()
  }, [url])

  return { data, loading, error }
}

// Any component — clean and simple
const { data: users, loading } = useFetch('/api/users')
const { data: posts }          = useFetch('/api/posts')
Single Responsibility
If your component name needs "and" in it (e.g. "FetchAndDisplayUsers"), split it into two.
Props drilling rule
Passing props through 3+ levels without using them? Time for Context or a state manager.
Lifting state up
Shared state belongs in the lowest common ancestor of the components that need it.

Step 1 — create a shared axios instance
// api/client.js — create once, import everywhere
import axios from 'axios'

const client = axios.create({
  baseURL: 'https://api.yourapp.com',
  timeout: 10_000,
  headers: { 'Content-Type': 'application/json' }
})

// Attach auth token to every request
client.interceptors.request.use(config => {
  config.headers.Authorization = `Bearer ${getToken()}`
  return config
})

// Handle 401 globally — no repeat code in components
client.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 401) redirectToLogin()
    return Promise.reject(error)
  }
)

export default client
Step 2 — full CRUD with proper error handling
// GET with abort on unmount
useEffect(() => {
  const controller = new AbortController()

  const loadUsers = async () => {
    setLoading(true)
    try {
      const { data } = await client.get('/users', {
        signal: controller.signal
      })
      setUsers(data)
    } catch (err) {
      if (!axios.isCancel(err)) setError(err.message)
    } finally {
      setLoading(false)
    }
  }

  loadUsers()
  return () => controller.abort()  // prevents state update on unmount
}, [])

// POST — create
await client.post('/users', { name: 'Priya', role: 'admin' })

// PUT — full replace  |  PATCH — partial update
await client.put(`/users/${id}`, updatedUser)
await client.patch(`/users/${id}`, { name: 'Ravi' })

// DELETE
await client.delete(`/users/${id}`)
Always abort on unmount
AbortController cancels in-flight requests when the component unmounts. Prevents the "setState on unmounted component" warning.
Interceptors = DRY code
Auth headers and 401 handling belong in interceptors — not copy-pasted in every component.
3 states always
Always track data, loading, and error. Show a skeleton while loading; never leave users staring at a blank screen.

Full pattern — Context + useReducer (the power combo)
// contexts/ThemeContext.jsx
import { createContext, useContext, useReducer } from 'react'

const ThemeCtx = createContext(null)

const reducer = (state, action) => {
  switch (action.type) {
    case 'TOGGLE_THEME':
      return { ...state, theme: state.theme === 'dark' ? 'light' : 'dark' }
    case 'SET_LANG':
      return { ...state, lang: action.lang }
    default: return state
  }
}

// Provider — wrap your app (or a subtree) with this
export function ThemeProvider({ children }) {
  const [state, dispatch] = useReducer(reducer, { theme: 'dark', lang: 'EN' })
  return (
    <ThemeCtx.Provider value={{ ...state, dispatch }}>
      {children}
    </ThemeCtx.Provider>
  )
}

// Custom hook — always expose context through a hook, not raw useContext
export function useTheme() {
  const ctx = useContext(ThemeCtx)
  if (!ctx) throw new Error('useTheme must be used inside ThemeProvider')
  return ctx
}

// In ANY component, anywhere in the tree — no props needed
const { theme, dispatch } = useTheme()
dispatch({ type: 'TOGGLE_THEME' })
Decision guide — when to use what
useState
→
Simple local state — form fields, toggles, counters
useReducer
→
Complex state with multiple fields or action types
Context API
→
Global/shared state — auth, theme, locale, user prefs
Zustand/Redux
→
Large teams, devtools, complex async middleware, high-freq updates
Split context by frequency
Auth (changes rarely) and UI theme (can change often) should be separate contexts to avoid unnecessary re-renders throughout your tree.
Context vs Redux
Context + useReducer handles 90% of apps. Add Zustand or Redux only when you need time-travel devtools or complex middleware.
Always use a custom hook
Wrap useContext in a custom hook like useTheme(). It's cleaner, adds the "used outside provider" error, and is easier to refactor.
