📁 Chapter 5
Feature-Based Folder Structure
The architecture pattern used by production codebases at scale. Every feature is a self-contained module with its own components, hooks, services, and types — nothing leaks across boundaries except through explicit public APIs.
Co-location
Files that change together live together. When you modify orders, you only touch src/features/orders/ — not scattered files across 5 folders.
Index Barrel
Each feature exposes a public index.ts — outsiders import from there, never from internal files. Refactoring stays contained.
Shared vs Feature
Only truly reusable UI (Button, Modal) goes in shared/. Business logic lives in the feature. Don't over-genericise early.

staleTime vs gcTime
staleTime: how long data is "fresh" (no background refetch). gcTime: how long unused cache is kept in memory. These are different knobs.
Index barrel exports
Import from features/products, never features/products/ProductCard. The barrel owns what's public. This makes refactoring internal structure safe.
types.ts naming
Prefix types with the feature: Product, ProductFilters, CreateProductDto. Avoids naming collisions when everything imports to one place.
⚡ Chapter 6
TanStack Query
The industry standard for async state management. Replaces useEffect + useState for every API call. Gives you caching, background refetch, loading/error states, and pagination — for free.
Query lifecycle — every state you need to handle
isPendingFirst load — no data in cache yet. Show skeleton/spinner.
isSuccessData fetched successfully. data is available. This is your happy path.
isErrorRequest failed. error contains the thrown value. Show error UI.
isFetchingBackground refetch in progress (data exists but is being refreshed). Show subtle loading indicator.
isStaleData is older than staleTime. Will refetch on next mount/focus. Usually you don't need to check this.

Exhaustive state handling in a component
function ProductList() {
  const { data, isPending, isError, isFetching, error } = useProducts()

  if (isPending) return <Skeleton />          // first load
  if (isError)   return <ErrorBanner msg={error.message} />

  return (
    <div>
      {isFetching && <TopLoadingBar />}  {/* subtle bg refetch */}
      {data.map(p => <ProductCard key={p.id} product={p} />)}
    </div>
  )
}

// ── productsApi.ts ─────────────────────────────────────
import { Product, ProductFilters } from './products.types'
import { api } from '@/shared/lib/axios'

export const getProducts = (filters: ProductFilters) =>
  api.get<Product[]>('/products', { params: filters })
    .then(res => res.data)

export const getProductById = (id: number) =>
  api.get<Product>(`/products/${id}`).then(res => res.data)

// ── useProducts.ts ─────────────────────────────────────
import { useQuery } from '@tanstack/react-query'
import { getProducts, getProductById } from './productsApi'
import type { ProductFilters } from './products.types'

// Query key factory — keeps keys consistent across the feature
export const productKeys = {
  all:     () => ['products']                       as const,
  lists:   () => [...productKeys.all(), 'list']    as const,
  list:    (f: ProductFilters) =>
             [...productKeys.lists(), f]            as const,
  details: () => [...productKeys.all(), 'detail']  as const,
  detail:  (id: number) =>
             [...productKeys.details(), id]         as const,
}

export function useProducts(filters: ProductFilters = {}) {
  return useQuery({
    queryKey: productKeys.list(filters),
    queryFn:  () => getProducts(filters),
    staleTime: 1000 * 60,          // override per-hook if needed
  })
}

export function useProduct(id: number) {
  return useQuery({
    queryKey: productKeys.detail(id),
    queryFn:  () => getProductById(id),
    enabled:  !!id,                   // don't run if id is falsy
  })
}
Why query key factories? When you invalidate productKeys.lists(), it invalidates ALL product list queries regardless of filters. When you invalidate productKeys.detail(5), only that specific product cache is cleared. Hierarchical keys = surgical cache control.
useMutation with optimistic updates
// ── useProductMutations.ts ─────────────────────────────
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { createProduct, updateProduct, deleteProduct } from './productsApi'
import { productKeys } from './useProducts'
import type { Product, CreateProductDto } from './products.types'

export function useCreateProduct() {
  const qc = useQueryClient()

  return useMutation({
    mutationFn: (dto: CreateProductDto) => createProduct(dto),

    // After success: tell TanStack to refetch all product lists
    onSuccess: () => {
      qc.invalidateQueries({ queryKey: productKeys.lists() })
    },
  })
}

export function useDeleteProduct() {
  const qc = useQueryClient()

  return useMutation({
    mutationFn: (id: number) => deleteProduct(id),

    // OPTIMISTIC UPDATE — remove from cache before server responds
    onMutate: async (deletedId) => {
      // Cancel any in-flight refetches (avoid overwriting optimistic update)
      await qc.cancelQueries({ queryKey: productKeys.lists() })

      // Snapshot the previous value (for rollback)
      const previous = qc.getQueryData<Product[]>(productKeys.lists())

      // Optimistically remove from cache immediately
      qc.setQueryData<Product[]>(productKeys.lists(), old =>
        old?.filter(p => p.id !== deletedId) ?? []
      )

      return { previous }  // passed to onError as context
    },

    // If server rejects, roll back to snapshot
    onError: (err, deletedId, context) => {
      qc.setQueryData(productKeys.lists(), context?.previous)
    },

    // Always sync cache with server truth after success or error
    onSettled: () => {
      qc.invalidateQueries({ queryKey: productKeys.lists() })
    },
  })
}

// Usage in a component:
const { mutate: createProduct, isPending, isError } = useCreateProduct()
<button onClick={() => createProduct({ name: 'Widget', price: 99 })} disabled={isPending}>
  {isPending ? 'Saving…' : 'Save'}
</button>
onSuccess → invalidate
The standard pattern. After a create/update/delete, call invalidateQueries — TanStack refetches in background, UI updates automatically.
onMutate → optimistic
Update the cache before the server responds. If it fails, onError rolls back. Feels instant to the user.
Query key factory — the pattern every project needs
// Hierarchical key structure enables surgical cache invalidation:

productKeys.all()           // → ['products']
productKeys.lists()         // → ['products', 'list']
productKeys.list({})        // → ['products', 'list', {}]
productKeys.list({cat:'A'}) // → ['products', 'list', {cat:'A'}]
productKeys.details()       // → ['products', 'detail']
productKeys.detail(5)       // → ['products', 'detail', 5]

// Invalidate scenarios:
qc.invalidateQueries({ queryKey: productKeys.all() })
// → Clears ALL product queries (lists + details)

qc.invalidateQueries({ queryKey: productKeys.lists() })
// → Clears only list queries (all filter combinations)

qc.invalidateQueries({ queryKey: productKeys.detail(5) })
// → Clears only the cache for product with id = 5
Rule: Always use a query key factory. Never write inline arrays like ['products', id] in components. String typos cause silent cache misses that are very hard to debug.

import {
  createRouter, createRoute, createRootRoute, createLazyRoute
} from '@tanstack/react-router'
import { queryClient } from '@/shared/lib/queryClient'
import { getProducts } from '@/features/products'
import { productKeys } from '@/features/products'

// Root layout — wraps everything
const rootRoute = createRootRoute({
  component: () => <RootLayout />,
})

// Auth guard layout — redirects if not logged in
const authRoute = createRoute({
  getParentRoute: () => rootRoute,
  id: '_auth',
  beforeLoad: ({ context }) => {
    if (!context.auth.isLoggedIn) {
      throw redirect({ to: '/login' })
    }
  },
})

// Products list — with loader that prefetches data
const productsRoute = createRoute({
  getParentRoute: () => authRoute,
  path: '/products',
  loader: () => queryClient.ensureQueryData({
    queryKey: productKeys.lists(),
    queryFn: () => getProducts({}),
  }),
  component: lazyImport(() => import('@/features/products/ProductListPage')),
})

// Product detail — typed $id param
const productDetailRoute = createRoute({
  getParentRoute: () => authRoute,
  path: '/products/$id',   // $id is typed as string, validate below
  params: { parse: ({ id }) => ({ id: Number(id) }) },
  loader: ({ params }) => queryClient.ensureQueryData({
    queryKey: productKeys.detail(params.id),
    queryFn: () => getProductById(params.id),
  }),
  component: lazyImport(() => import('@/features/products/ProductDetailPage')),
})

export const router = createRouter({
  routeTree: rootRoute.addChildren([
    loginRoute,
    authRoute.addChildren([productsRoute, productDetailRoute, ordersRoute]),
  ]),
  context: { auth: undefined! }, // injected at root
})

function ProductListPage() {
  // This query NEVER shows isPending when loader ran ensureQueryData
  const { data } = useProducts()  // ← instant cache hit
  return <ProductGrid products={data!} />
}
Key insight: The loader populates the TanStack Query cache. When the component mounts and calls useQuery, it finds data already in cache — no loading state, no flash of empty content.
beforeLoad — type-safe auth guards
// ── routeGuards.tsx ─────────────────────────────────────
import { redirect } from '@tanstack/react-router'

// Reusable guard — throw redirect if not authenticated
export const requireAuth = ({ context }: { context: RouterContext }) => {
  if (!context.auth.isLoggedIn) {
    throw redirect({
      to: '/login',
      search: { redirect: location.pathname }, // typed!
    })
  }
}

// Role guard
export const requireRole = (role: 'admin' | 'user') =>
  ({ context }: { context: RouterContext }) => {
    if (!context.auth.roles.includes(role)) {
      throw redirect({ to: '/unauthorized' })
    }
  }

// Apply to a layout route — all children inherit the guard
const authRoute = createRoute({
  getParentRoute: () => rootRoute,
  id: '_auth',
  beforeLoad: requireAuth,
})

const adminRoute = createRoute({
  getParentRoute: () => authRoute,
  id: '_admin',
  beforeLoad: requireRole('admin'),
})
Throw redirect
Guards use throw redirect() — not return. The throw halts the route transition and navigates. TypeScript verifies the to path exists.
Layout guards
Attach the guard to a layout route (e.g. _auth). All nested routes inherit it automatically — no copy-paste per route.

main.tsx — wiring all providers together
import React from 'react'
import { createRoot } from 'react-dom/client'
import { QueryClientProvider } from '@tanstack/react-query'
import { ReactQueryDevtools } from '@tanstack/react-query-devtools'
import { RouterProvider } from '@tanstack/react-router'
import { queryClient } from '@/shared/lib/queryClient'
import { router } from '@/router/routes'
import { useAuthContext } from '@/features/auth'

function App() {
  const auth = useAuthContext()  // injected into router context

  return (
    <QueryClientProvider client={queryClient}>
      <RouterProvider router={router} context={{ auth }} />
      <ReactQueryDevtools initialIsOpen={false} />  {/* debug panel */}
    </QueryClientProvider>
  )
}

createRoot(document.getElementById('root')!).render(<App />)
Complete data flow — user navigates to /products?category=tools
1. URL
User navigates to /products?category=tools. TanStack Router matches the productsRoute. Zod validates and parses the search params.
2. LOADER
Route loader() runs. Calls queryClient.ensureQueryData with productKeys.list({category:'tools'}). API call fires.
3. CACHE
TanStack Query stores response under key ['products','list',{category:'tools'}]. Data is "fresh" for staleTime ms.
4. RENDER
ProductListPage mounts. useProducts({category:'tools'}) reads from cache — isPending is false instantly. No spinner.
5. FILTER
User changes filter in search input. navigate({search: prev => ...}) updates URL. useProducts re-runs with new key — TanStack Query fetches or serves from cache.
